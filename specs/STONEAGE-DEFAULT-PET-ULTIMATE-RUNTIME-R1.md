# Explicit default pet selection and ultimate exit runtime R1

Status: LOCAL_VALIDATED; exact remote input/gates pending.

## Corrected behavior

An explicit immutable `DefaultPetExitAuthority` binds owner identity, nullable
selected roster identity, owned pet identities and occupied reduced-layout
battle slots. Selection may refer to an owned pet absent from active battle;
zero HP does not itself erase battle occupancy. Missing authority on a player
or pet ultimate exit fails closed. The driver never counts allied pets to guess
selection. Occupancy collisions, conflicting owners and selected unowned pets
reject before committing an immutable persistent transaction.

Player ultimate handling uses the exact selected identity for the helper Exit,
then separately clears the owner's `i+5` occupied entry. Explicit no selection
skips the selected helper without skipping paired cleanup. Selected and paired
identities are deduplicated only when they actually coincide; unrelated pets
are neither selected nor treated as the player's carried roster. A selected
pet absent/already exited from battle is not re-entered or replaced by another
pet. Player ultimate itself preserves DEFAULTPET for the source loyalty read.

Pet ultimate clears its explicit owner's selection even when that pet was not
the currently selected pet. The fatal event records the semantic owner clear.
Ordinary and shared nonbow multihit paths update current selection before later
actions/hits and the persistent profit event walk reads clears chronologically.
Recall clears also update the current authority. A pet ultimate followed by
player death therefore incurs the pet's own death penalty once, without an
extra player-death default-pet penalty to the cleared selection.

The persistent adapter derives authority from the actual session roster,
DEFAULTPET source slot and battle occupancy/exited identities, and includes
dead owned entries absent from the prepared living queue. Player Exit restores
their HP to1 and clears their common status while retaining ownership. Ordinary
and continuation return exact exits; later actors skip them. The dedicated
player ultimate terminal still excludes final EXP/items and reads explicit
elder-return input. The simple nonpersistent runtime shell forwards optional
explicit authority and fails closed on a lethal exit without it.

## Historical boundary

helper/static exit observations. The `i+5` mapping is the declared reduced
SIDE_OFFSET10 layout, not a guessed full multiplayer or original build profile.
Low-level synthetic witnesses explicitly declare occupancy/ownership, including
separate selected/paired identities; they are not evidence that those synthetic
arrangements were normally generated by historical Entry.

The carried roster in this base subset represents non-mail pets. No source
profile, numeric guarded COM1, charset, equipment, ride/counter extension or
Taiwan-v1 membership is inferred. Existing native486 DEFAULTPET helper cases
use controlled getters/Exit stubs; static player cleanup anchors are not a full
native Exit/UltimateExtra/AddProfit composition certificate. Full native
death-scan ordering/multi-victim profit composition remains OPEN.

BattleModel remains explicitly nonlethal. This correction to common exit state
does not enable lethal638 or promote either of its two positive slots.
