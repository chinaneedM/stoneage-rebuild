# PET-DETAIL10｜124份宠物的后期PC基础面板理论区间，以及台湾1.0原K包不兼容边界

**本页绝非原台湾1.0的官方出生属性。** 为回应「原游戏怎么生成宠物、难道没有初始数值」的问题，直接沿**2016年社区保存的PC原C代码**，把已恢复的195条模板出生中间值连接到后续基础面板属性计算代码。所有数值仍是**后期PC源码的未装备、未其他修饰、数学有理数近似截断模型**，不代表台湾1.0的出生HP／攻击／防御／敏捷，也不代表运行于实际2016服务器的随机分布。

## 这次新查到的两处原代码

- [2016年固定来源PC服务端 `gmsv/src/char/char.c`](https://github.com/pimpcapital/longzoro-sa/blob/57b14e2bb373ba851c14db28a239273e4a8831bb/gmsv/src/char/char.c)：`CHAR_initcharWorkInt`计算`CHAR_WORKMAXHP / CHAR_WORKFIXSTR / CHAR_WORKFIXTOUGH / CHAR_WORKFIXDEX`，`_CHAR_complianceParameter`把基础攻击／防御／速度映射到`CHAR_WORKATTACKPOWER / CHAR_WORKDEFENCEPOWER / CHAR_WORKQUICK`，随后仍可由装备/其他来源修改。原Git Blob `5a044dc68bb76758b2a757a8e83c10b93578be31`。
- [台湾1.0原`sa_3.exe`静态K包解码证据](../../research/recovered/STONEAGE-PET126E-TW10-K-STATUS-CAPTURE-STATIC-R1.json)：原EXE SHA-256 `cdab9ea049a98bbc96ce93eeaa8b63c688f0c0f0ad8b3183e79d75e47621441a`；20个字段有原本机指令窗口的地址与结构偏移见PET126E。本批复用其原静态证据，没有获得同一台湾1.0官服的服务端发送器或执行原客户端。

## 2016代码的基础面板换算

以下`V、S、T、D`均为 **2016 PC服务端生成时的内部初始生命、力量、耐力、速度**。这里的「最大生命」是基础`CHAR_WORKMAXHP`，尚未证明出生UI，亦未包含装备和其他参数修改。

| 后期PC计算字段 | 原代码等价的有理数表达式（整数截断） |
|---|---|
| 基础最大生命（Max HP） | `(4V + S + T + D) / 100` |
| 基础攻击 | `(2V + 20S + 2T + D) / 2000` |
| 基础防御 | `(2V + 2S + 20T + D) / 2000` |
| 基础敏捷 | `D / 100` |

每个模板Lv1初始内部基础为`INITNUM × (BASE + 每项独立−2～+2 + 在四项间随机分配共10点)`，因此对**单个**显示属性，数学最小值取各基础偏移−2且把10个点分给其权重最小的基础，最大值取+2且把10点分给权重最大的基础。**不能把四列的各自最大值看作同一只宠物同时可达。** 本批把195模板×4字段＝**780条**可追溯数学包络写入机读库并逐宠展示。

此外，C源码的攻击/防御包含浮点常数，HP中间还使用`float`，再转整数；**下面数学有理数理论包络不等于编译运行后的逐ULP极值**。`ITEM_equipEffect`、`Other_DefcharWorkInt`等处理亦未被省略为“不存在”。若要确认准确的原游戏面板出生区间，还必须实际执行对应构建、核C编译精度与运行时后处理，获得同版本官方服务端来源。

## 更重要的版本边界：早期K包前18个数字字段对应，但全包不兼容

独立核对台湾1.0原`sa_3.exe`静态`S/K`解码表与2016 PC `CHAR_makeStatusString('k')`序列，二者的前18个数值字段（**字段token 2–19**）意义依次对应：图形号、当前HP、最大HP、MP、最大MP、EXP、升级所需EXP、等级、攻击、防御、敏捷、忠诚、地/水/火/风、技能槽容量、改名权限。

但**从token 20开始不再同格式**：

| token位置 | 台湾1.0原客户端希望收到 | 2016后期源码发送（未编译`_SHOW_FUSION`） |
|---|---|---|
| 2–19 | 18个原数值字段 | 同顺序的18个数值字段 |
| **20** | **宠物名称字符串** | **宠物转生数整数** |
| 21 | 自定义名称字符串 | 宠物名称字符串 |
| 22 | 早期20字段记录内无此字段 | 自定义名称字符串 |

如果2016服务器编译启用了`_SHOW_FUSION`，它还会在名称前再加入一个融合转生相关数值字段，文本名称额外后移。因此**不能直接把2016服务器与台湾1.0客户端视为协议兼容**，更不能用它的数值直接填早期宠物原服属性。这仅是两份原本机/源代码的**静态字段比较**，不是本轮成功连接运行的证据。
