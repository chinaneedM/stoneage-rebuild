# 宠物档案自主编号与跨版本证据关联规则 R1（2026-11-21）

**决定：我们自己编编号，原石器 PC 的数字一律作为带来源的“原号”保存。** 该规则面向未来统一宠物图鉴、新单机的数据导入与历史考据，不改变当前 PET 唯一模块或历史验收门槛。

## 一、只需区分两种自己的编号

| 编号 | 例子 | 用途 | 是否表示原版实际发放宠物 |
| --- | --- | --- | --- |
| **宠物档案号** | **`PET-000001`**（乌力） | 以后用户查看、统计和引用的**永久主编号**；首次建立单只详细档案时分配 | **不表示**，档案可以部分完成 |
| **来源观察号** | `OBS-TW10-0001`（台湾 1.0 相簿第1条） | 一条原客户端/原公告/图鉴的证据记录；当前124条台湾1.0候选均有OBS号 | **不表示**，没有建立档案不能计为已恢复宠物 |

原版号码要完整留下，例如台湾1.0乌力客户端原SPR图号 **100250**、组号 **240**、头像RD号 **7246**；其中100250**不是我们的宠物号，也不能冒充原版服务器宠物ID**。以后另有日文、韩文或大陆客户端证据时建对应OBS来源记录；若身份确认可以指向同一PET档案，不覆盖原号码。

机器索引：[PET-ID-REGISTRY-R1.json](../../research/pets/PET-ID-REGISTRY-R1.json)。以[机读编号登记簿](../../research/pets/PET-ID-REGISTRY-R1.json)为实时准据；截至本次 PET-PROFILE-BATCH03 已建 `PET-000001`—`PET-000025` 共25份部分档案、OBS来源记录124条、未建档99条、完整历史验收0只。这里的“25份”只指单独有档案，**不指25种官服已发放宠物**。

## 二、分配与合并（避免未来推倒重编）

1. `PET-` 是6位顺序流水：`PET-000001`、`PET-000002`……只有**建立单只可查看档案**时才占号；历史年代、攻击、稀有度、原图号、属于哪个系均**不能决定流水号**。
2. 任何已分配编号**永久不改、不回收、不重排**。源文本改名、发现是不同版或证据推翻时保留旧号与变更/重定向历史，不能默默删除。
3. `OBS-` 是“来源版本代码+源内顺序”。台湾1.0的124条序号稳定是 `OBS-TW10-0001` 至 `OBS-TW10-0124`；不生成124个假的PET档案，也不宣称124只官方在服宠物。
4. 多个版本**同图、同名、同SPR原段SHA**仅表示关联候选，不能据此宣布两版同一种、统一宠物ID或取得方式。形成经史料证实的同物种身份后才归到相同PET号；不同品系、配色、变种和跨服数值保留**各版本独立记录**。
5. 若两个已建PET档后来确认为同种，采用**保留旧编号的别名/合并重定向**，不重新使用旧编号；若发现某条源记录只是占位，则标记撤销或非宠物，不计历史实发物种。
6. 用户原创单机设计使用独立设计层（例如将来 `GAME-PET-`），不得反向伪造历史客户端、数值或技能，当前不启动 Stage B。

## 三、一只宠物应记录的完整但可渐进填写的内容

- **身份**：内部档案号、原号集合、原始姓名/多地区别名、族系/变体、首次实证时间、是否真正在官服投放、源证可信度。
- **基础能力**：各版初始等级/HP/攻击/防御/敏捷、基础生命/腕力/耐力/速度、四元素、初始随机上下界与分布、成长/等级算法、等级上限、转生/融合前后修正。
- **技能行为**：自带与可学技能（名称、技能ID、槽位、触发等级、伤害/命中/异常公式、学习条件），基本攻击/防御/AI行动；未证实运行公式时不填写。
- **2D图像动作**：原SPR组、RD头像、图鉴、颜色/配色候选、方向和动作码、逐帧资源、声音和特效，动作码与游戏语义/实际帧率独立确认。
- **获得方式**：野外地图ID/名称/坐标、遇敌等级和概率、捕捉条件及道具、初始赠送、任务/活动/运营奖励、各版本上线退场日期；缺原资料就留空。
- **图鉴背景**：原版描述、生态与栖息地、系谱关系、骑乘/进化/融合/特殊变体、各版相关任务和官方剧情；“未实装”和“未查到”要不同标记。
- **证据与进度**：每一个关键值的来源版本/载体/原行SHA/取证日期、证据等级、是否复核、待补问题；将**客户端图形候选/已建档/全字段验收**分开计数。

**使用最简结构**：一张PET主档+各个OBS来源记录+版本证据字段，不提前设计复杂的世界数据库；当前原创游戏与攻略网站继续保持 GATED。
