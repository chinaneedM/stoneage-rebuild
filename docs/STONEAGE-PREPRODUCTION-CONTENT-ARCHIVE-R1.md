# 《石器时代》设计前历史资料库｜全域目录与未来玩家资料站数据规范 R1

2026-10-17。**这不是已完成的全内容数据库，也不是已经建成的游戏/网站。** 用户明确追加的工作目标：原版/历代的任务内容、NPC、全部宠物与成长、人物二维模型、登录与交互界面、地图/音效、各时期外挂的全部功能；要先充分整理史料再讨论新作。未来考虑如昔日游戏官网一样拥有可按任务/宠物等检索的玩家参考网站。这里先把长期成果拆成**可归档、可校验、可追加**的原始来源资料模型。

## 一、先确定“全面整理”的含义

**目标是尽可能穷尽可认证的史料与来源，再明确缺失，而不是猜“已经100%”。** 对每个版本同时保留：可见实体目录、旧名称/ID、地域年代、记录出处、原始截图/官方原文的可查证指针、资源身份/可用版权状态、测试/兼容说明，以及**缺失字段的显式UNKNOWN**。不能以晚期私服大全替代1999/JSS首发的名单。

优先参考七类严格隔离的版本：`JSS1999_ORIGIN`、`TW10`、`CN182`、`RECOVERED25`、按版本细分的后期官方/商业内容、私服与现代社区衍生、最终`NEW_GAME`原创。后期官方游戏、现代石器手游、同名IP续作和不同私服需再区分作者/运营/产品，不能自动同源合并。

## 二、每类资料必须通过“身份—内容—表现—行为”关联

机器清单 `research/recovered/STONEAGE-PREPRODUCTION-CONTENT-ARCHIVE-R1.json` 首次列出**22个准备工作领域、15个关键跨系统关联门**。每条关联由准确版本、两端实际ID、记录类型与来源支持，分别标记其完成度。不能因为两张表都含相似编号就当同一东西。

最重要的可核验关联例子：

- **人物**：`CreateNewChar.body_image_id / face_image_id` → 原版人物身份与二维头像、精灵动画 → 创建画面的真正显示选择。当前证实的是原数据字段，完整显示连接尚不成立。
- **宠物**：`S:K.graphic_id` → 原版同版资源SPR组 → 状态/朝向/动作/帧 → 玩家画面与战斗。缺少v1客户端真实调用链不能逐图任意分配物种。
- **宠物成长**：物种模板→四项基础值→个体偏移/等级公式→原始EXP→宠物技能/产地；后代988个active enemybase记录不是988种首代宠物。
- **任务**：版本化NPC→同版地图与坐标→对白选择→物品/事件标记→真实奖励→离线持久态。后代NPC脚本只能在自己版本下认证。
- **外挂**：工具家族→真实软件版本→发布日期证据→功能首次出现→输入条件/判断/输出/边界→将来讨论是否作为新游戏内建功能。历史层**全部功能都应列出，包括不打算采用的滥用功能**，但不需要执行旧版漏洞、复制账号工具或修改商用服务端。

## 三、未来玩家资料网站：现在规划一套数据，未来可双用途

建议统一数据流：
`史料/资源指纹→版本分层解析→实体关系表+明确UNKNOWN→研究审阅→可公开/可用授权筛选→游戏内容候选与网站查询`。

这意味着同一份资料将来可支持“宠物图鉴、可抓地点、成长机制、技能”“NPC与任务导航”“地图与村庄服务”“料理道具”“官方与民间版本演化”“外挂历史百科”。网站设计的直接参考是当年可查询的游戏资料站体验，**不是复制别人的网页布局或版权图片**。

已约定未来每条网站数据至少包含：`record_id`、`entity_type`、`version_profile`、`source_refs`、`verification_status`、`rights_status` 和 `record_revision`。可选字段包括历史别名、精灵/动作、交互条件、攻略、数值、关联人物与多语言文本。资料有矛盾就展示来源对照，不能无声采用其中某条。

未来网页要能让用户按版本浏览、按宠物和任务检索、查看来源及修订历史，并区分“已确认、仅后代、资料不足、新作设定”。技术上现在**不选网站框架、域名、服务器，不启动网页开发**。

## 四、目前真正的优先级和验收纪律

1. **PET-ASSET-GROWTH-CATALOG-MATRIX-02**：来源一致的宠物身份/资源/成长表及未匹配列表。只认证真的跨表连接，未知不可补零。
2. **ORIGINAL-UI-LOGIN-AVATAR-REVIEW-01**：登录、选角、人物角色动画、HUD、NPC窗口、战斗界面的原始截图/真实选择路径/资源关联。
3. **WORLD-NPC-QUEST-SOURCE-JOIN-01**：早期村落→NPC→任务→奖励与真实状态的版本化证据链。
4. **LEGACY-ASSISTANT-FULL-FEATURE-ARCHIVE-01**：不论以后采纳与否，将能查证的工具和全部功能按版本保管，未检索到/未能确认的明确记UNKNOWN。**历史功能整理与作弊执行代码是两回事**。
5. **HISTORICAL-SITE-IA-AND-WIKI-EXPORT-CONTRACT-01**：核查早年官网和现有资料网站，形成供未来公开知识库筛选的机器可读输出规范。

每一步都应真实新增“可使用的分版本条目、实际链接或明确缺口”，而非只增加R号和测试数量。已通过的Stage A证据受限审阅保持历史真实；因用户新需求允许**有名的领域复原**，但不擅自开启新引擎/新剧情/玩家网站的生产工作。

**本轮交付范围：22域、7版本profile、15个未证实全链连接、19个未来网站集合、一套严格导出字段和验收工具。均是资料准备骨架，不声称对应原始实体全集已收齐。**


## 2026-10-18用户范围澄清：全官方版本参考库（DD-027）

用户明确希望宠物、任务及其它所有官方版本的资料、模型与玩法都可收集，供后续新石器参考，即使最终不用。资料准备采用相连的两条线：早期版本复原基准，以及全官方版本参考库。后期官方内容可以在自身版本下独立成立并值得收集，不以先证明TW1.0同版为其入库前提；涉及初代归属的结论仍须初代证据。

既有7个profile是资料类别，不是所有官方产品/地区/补丁已列齐的证明。逐步建立官方发行/运营/语言/版本/构建/日期/临时活动覆盖账本；无法认证的留UNKNOWN。不同IP衍生产品单列，社区改造/私服和外挂机制沿既有独立类别保存。

收藏对象覆盖宠物物种/变种/属性/成长/捕获/产地/技能/骑乘，NPC/对白/任务条件与步骤/奖励/活动，人物/地图/二维精灵或有来源的三维模型/动画/界面，道具/合成/料理/经济/战斗/社交/养成/官方辅助玩法。每条均保留具体版本、原名/ID及可信别名、来源/时间、表现与行为、完整程度、版权和缺失字段；跨版增加/改名/删除/数值变更另列对照。相同名称或ID不能自动合并实体。

执行顺序为发行与来源目录→可核验内容表/视觉参考→有价值差异对照，复用未变内容、有限分包，不逐个补丁重复下载。没有采用意向的内容也保留为历史/设计参考。未来共同设计时再决定采用、改造或舍弃，原版权资产不自动成为生产素材。全官方范围是长期收集目标，缺源条目明确登记；不要求无限等待全部版本无缺口才允许阶段审阅。


## 2026-10-18补充：官方世界历史与版本叙事连接

用户希望各官方版本更新、历史故事的关系成为未来世界观的参考，并委托助手主动查缺。资料库增加两份相互关联而独立的时间线：现实发行/运营/补丁时间，以及虚构世界内部事件先后。每条叙事连接记录两端具体版本/人物/地点/任务、来源、关系类型、证据等级及冲突；关系区分续接/前传、地区或平行分支、译名差异、设定改写/矛盾、纯机制调整与UNKNOWN。更新日期不直接当世界内年份，所有官方版本不预设同一条无矛盾时间线。

研究问题同时覆盖地理迁徙与文明、族群/势力/信仰与神话、宠物生态/栖息地/人与宠物关系、人物动机/任务前因后果、事件是否永久改变世界、日常经济/技术，以及玩家从新手到伙伴培养/首次骑宠的成长体验。系统资料补充最早有证据版本、变化、官方叙事语境、玩法作用和可见取舍；作者原意需来源，研究解释记HYPOTHESIS，新石器补充设定记DESIGN。缺证不编造古史或因果。

这些是既有22域的跨域关系与待查维度，不宣称已恢复新增世界观事实，不用另起概念清单替代实际取源。后续材料评审主动检查遗漏，优先能增加具名人物/任务/场景和版本关系的有限来源；是否吸收及如何整合仍由后续共同设计决定。
