# 游戏任务来源分类 R1 — 本体、永久版本内容、运营活动与待考

**决策日期：**2026-10-24。**性质：**史料分类及来源归属规则，不是新的《石器时代》生产设计、也不宣称取得原服务器或新增历史实体。源于项目所有者本轮明确要求：**活动任务与游戏本体任务必须严格分开；节日和特别日期由各运营公司推出的活动，不应混入游戏本体任务目录。**

## 任务起源的四个互斥主档

| 分类 | 判断门槛 | 资料库位置与用法 |
|---|---|---|
| `BASE_GAME_QUEST` 游戏本体原有任务 | 有该**具体地区、版本/发售基线**原生任务或同步期可信官方内容证据；不能只靠年代、任务名称、网民攻略来断定 | 本体主任务/支线任务目录，保留其成立版本 |
| `PERMANENT_VERSION_QUEST` 后续版本永久任务 | 可证作为持续内容通过某版本更新加入，**不属于限时活动**，记录首次可证版本、前后差异 | 后续正式版本的常规任务目录；不得写作最初发行已有 |
| `OPERATOR_EVENT_QUEST` 运营活动任务或活动 | 有明确节日、周年、特殊活动、运营组织或时间/投放语境；期限可以未知，**不得因此补造停止日期** | 按公司×地区×事件×年份整理的独立活动档；再区分有任务流程和仅人工领奖/GM活动 |
| `ORIGIN_UNRESOLVED` 任务归属待考 | 缺少足够证据证明本体、永久或活动任何一类 | 待考目录，不进入本体任务统计或确定性世界线 |

**分类起源**与**服务端真实上线是否验证**是不同维度。报纸、同期玩家攻略、运营方发布文（包括媒体转录）、官方客户端/脚本、原服记录按证据层级独立记载。即使确定属于节庆**档案主题**，也不能凭文章证明每一项服务器事务真实执行。某任务曾经开放不代表一直开放；某事件结束后永久留下的宠物、NPC、功能、物品亦不把事件任务变成本体。

## 每条任务档案必须保留的字段

任务或活动来源记录要有：`origin_class`，`record_kind`（有剧情/完成条件的任务、GM人工领奖、纯活动公告等），运营方、地区/语言、正式版本或 UNKNOWN、文献发布日期、宣称活动期与实际服务器运行证据、首次推出/后续复刻/是否转永久、原NPC和任务ID（无证据用null）、奖品/限定状态、证据类别及历史冲突。活动任务索引可列活动主题与故事素材用于后续世界观参考，但不自动进入游戏本体任务线，也不冒充原服剧情的固定顺序。

永久新增内容单独于**最初发行版原有内容**。同一个题名跨地区、跨年份复开，不因题名相似就合并为同一服务端实体。原官方补丁/公告或同版本主表才能支持提升。运营活动是否由特定公司负责必须有证据；媒体编辑栏、二次转载不能静默代替运营主体证明。

## 晋级与纠错门槛

`ORIGIN_UNRESOLVED` 升本体：至少找到同地区同构建发行任务证据，且能支持**发售基线存在**的归属；不能用“2003年有攻略”替代“2000年原版有任务”。升永久新增：正式版本更新/非临时常驻说明与最初出现版本。判为运营活动：运营方/发布/节庆/特别时段之一有明确可查出处，保留是否实际部署的独立不确定度。任何推翻既有分类的材料都做**新日期带理由订正**，不悄悄改写旧研究或覆盖收据。
