## 1. 我们现在拿到了什么

台湾 Waei/JSS v1.0 零售盘已被项目接受为基础样本，有411个盘内文件、383个核心客户端文件的清单与哈希。它能支撑原始资源、协议及状态结构的研究。普通场景地图经网络交付并形成客户端缓存；原始商业服的世界、NPC、任务、商品、奖励及权威角色数据不能由零售盘直接补齐。

规则与内容必须分层使用：

| 来源层 | 可以用来回答 | 使用限制 |
|---|---|---|
| V1_DIRECT：台湾1.0原始客户端 | 编译消息形状、字段位置、资源身份、文件边界 | 单有客户端接口，无法确定原始服务器发了什么内容 |
| EARLY_LINEAGE：早期协议/后代比较 | 与原形状匹配的字段语义和候选解释 | 解释及版本归属分别保留；不能把后代符号当原版二进制符号 |
| LATER_RECOVERED：recovered25及固定后代 | 对应来源版本的地图、NPC、规则和条件流程 | 后期资料不自动变成JSS1999、台湾1.0或大陆1.82事实 |
| MODERN_SYNTHETIC：现代参考实现 | 在显式输入下验证规则与状态衔接 | 测试中的地图、物品、数值和本地存盘不证明历史商业服结果 |

### 复跑入口与边界

在仓库根目录运行（Python 3.11，标准库）：

```bash
python tools/stoneage_stage_a_review_packet.py
python tools/stoneage_stage_a_review_packet.py --replay
```

第一条检查来源指纹、九族状态、七条体验、五个阻塞、历史连续性前缀和复跑入口。第二条再运行清单中的现有测试：原版状态/资源规格、后期路线的派生证据审查、现代捕宠/成长与商店/读档参考情景。它不联网、不下载原始客户端、不运行旧商业服，不会把后期路线审查说成重新游玩原始地图。各组输出保留自己的测试数和来源范围，不计算“整体复原百分比”。

## 4. 剩余阻塞如何处置

| 优先级/缺口 | 对复原的影响 | 允许重开的证据与停止点 |
|---|---|---|
| P0 初代服务端世界/NPC/任务/商品/奖赏 | 阻断精确恢复原初世界和内容循环 | 可数字取得且版本/来源可核验的同代资料或客户端—服务器记录；没有这些时保留OPEN，不编脚本/数值填满 |
| P1 人物/宠物当前态与EXP制度 | 阻断完整自动初始化和原初成长曲线 | 匹配版本的当前态、初始化及阈值资料；此前继续显式输入，互斥EXP制度不混用 |
| P1 奖励/事件/道具与商业存档 | 阻断任务进度与重登结果认证 | 同源道具标记、事件字段、原始ACK/重登轨迹；现代文件保存独立验收 |
| P2 原版视觉/操作绑定 | 阻断历史交互画面的完整复现 | 原版相关绘制/选择调用链或认证运行记录；不能仅凭资源编号、后期截图补映射 |
| 暂停：savedata R79 | 当前未证明其阻断具体核心玩法 | 只有新业务字段证据、具体规则冲突或最小必要依赖才重开；不穷举普通辅助函数 |

原始商业服务运行资料的可恢复性和客户端规格的可使用性是两个问题。资料缺失可以形成经审阅的证据受限记录；这不会把缺失内容恢复出来。早期资料搜索不要求用户购买实体或取得原始美术。只有会改变具体游戏规格/内容归属的新线索才进入下一工作包。
