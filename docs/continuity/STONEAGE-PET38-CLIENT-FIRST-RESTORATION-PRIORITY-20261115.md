## 今后的严格优先级（对所有年份一致）

1. **先盘点客户端版本**：按原年份、地区、运营商、产品线取得原安装盘/更新包，核SHA256、CRC、文件树、编译/版别证据；只拥有索引和摘要时不得说已重新读取了商业原件。
2. **先静态提取能提取的**：从本地包中的真实文件区分宠物类数据、图形号、SPR/ADRN/REAL、动作方向/帧、本地名称与技能字段；先保留源行、偏移、原始格式和多重候选关系，再进行去重和归类。
3. **同版本关联**：若有“原名→宠物ID→图形ID→原动作图”的*同版*可靠来源，才晋升成可检索的宠物资源身份；客户端里有图只能是`CLIENT_FILE_OR_SPR_PRESENT`，未必是该版本官服发布的宠。
4. **跨版本对比**：同一个资源号在两版都出现不代表同一物种；新增/移除仅是**两个已取得客户端快照之间的资源变化**，不能擅称首次发布。若原服仍由服务器控制捕捉、奖励、成长公式、技能效果，应继续缺失。
5. **仅针对缺件查外部**：有客户端却缺逐宠实装时，针对指定资源号去查同期官网更新/手册/活动/攻略；没有客户端先搜原安装包的可核存世线索，确实不可得才用当年正式来源做来源有界审查。不为凑进度继续重复泛查新闻和目录。
6. **分开输出两张查询视图**：① `client_asset_inventory` 已验原客户端资源与身份候选；② `official_live_pet_release_roster` 有正式运营/原生取得证据的宠物。阶段、年份和两类数目不混计。
