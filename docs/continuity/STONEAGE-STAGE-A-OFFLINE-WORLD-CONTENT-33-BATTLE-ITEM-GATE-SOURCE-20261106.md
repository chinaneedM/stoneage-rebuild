`ITEM_itemconfentries` 将原零基列 20／21 的 `fieldtype`／`target` 装入编译整数键 4／5，分别对应内存记录偏移 `+0x14`／`+0x18`。服务端物品状态字符串与客户端拆项指令提供静态接点。客户端将两个相邻数值分别写入物品行内的场景和目标字段，再由战斗物品栏、场外物品操作和战斗目标选择各自读取。状态字符串接点做静态核查，客户端回放从已有物品状态的夹具开始。

## 原指令核验

| `fieldtype` | 回复回调原表物理行 | 客户端战斗物品栏通过场景检查 | 客户端场外使用通过场景检查 |
| --- | ---: | --- | --- |
| 0 | 497 | 是 | 是 |
| 1 | 79 | 是 | 否 |
| 2 | 68 | 否 | 是 |

合计 644 条原物理行，含一条带 `#` 前缀的 13031。每种实存场景／目标组合取一个原行见证，共七组。13031 只提供物理行字段夹具，其历史加载仍不据此判断。客户端也核验了空槽和等级不足的拒绝。

服务端回放从 `lssproto_B_recv` 起，经 `BattleCommandDispach` 解析战斗物品命令。原指令读取角色背包槽、检查物品索引，再由 `ITEM_isTargetValid` 检查目标。用原属性访问器把登记结果写入夹具角色的战斗工作字段。连接身份、通知、时间和少量 C 库函数由夹具提供，回放至入口返回。

- **普通目标槽。** 对七组原行字段，槽 7 和 17 都通过该服务端入口。实测物品实例读取偏移为 `0`、`0`、`+0x18`，分别用于存在检查与目标读取。场景偏移 `+0x14` 没有被读取。原物品 12555（场景 2、目标 1）在客户端战斗物品栏被挡住，单独把普通槽位命令交给服务端时仍登记物品指令。原物品 12780（目标 0）的客户端目标选择走本人路径，服务端目标检查仍接受另一普通槽位。
- **群体目标。** 客户端目标类型 2／3 按施用者侧别分别构造同侧／对侧目标值 20、21，类型 4 构造目标 22。服务端对这三个群体值执行相应类型与侧别检查。无匹配群体目标、目标 23、背包缺物或命令解析失败时，改写为等待指令 11。正常物品登记值为 7。
- **证据止点。** 以上是客户端选择窗口和服务端命令登记。群体范围的结算、实战执行、客户端与服务端互通、网络通知和背包变更均未观察。场外使用的服务端入口及其它判定仍需单独取证。
