# PET-DETAIL16｜台湾1.0原生PC宠物技能：战斗菜单、目标分派与200／201数字ID原件

日期：2026-11-22。**只研究经典2D PC《石器时代》，PET是唯一内容模块。**

## 为什么本轮重新转向原件

PET-DETAIL15把2001—2004年的技能文字分别归档，但那些网页不足以给台湾1.0本服宠物填出生技能、技能效果和学习条件。本轮因此**实际再次访问、校验私人持有的原台湾1.0客户端压缩包以及真正的`source/sa_3.exe`**；不再依靠后期社区技能表推定原始程序行为，也不继续反复搜未取得字节的旧下载入口。

源ZIP **372,626,292字节**、SHA-256 `3a4854adaebef056332cdbd7b1dc1c130c571b11704e3f199f53d03aa31cba24`，共379成员；原`sa_3.exe` **425,984字节**、CRC32 `3453fd16`、SHA-256 `cdab9ea049a98bbc96ce93eeaa8b63c688f0c0f0ad8b3183e79d75e47621441a`。以GNU objdump（PE32/i386）独立反汇编，另用Python自己解析PE虚址→原文件节偏移，再读字节检查：**7/7原生代码窗口SHA、32/32反汇编地址/指令锚点、14/14原字节小端数值均通过**。原EXE没有启动运行、没有收到当年服务器消息，原商用文件及完整反汇编**绝不进入公开Git**。具体窗口地址/sha及操作数见[机器收据](../../research/pets/PET-DETAIL-EVIDENCE16-TW10-NATIVE-BATTLE-SKILL-ID-AND-TARGET-R1.json)。

## 新增一｜战斗界面真正读取W技能字段，而不止宠物资料界面显示

在原EXE代码`0x40380F`起的战斗技能菜单循环中，`0x403815`、`0x4038A5`、`0x4039E2`读取与PET-DETAIL13一致的**K技能槽容量**（原结构`+64`）；`0x4038D3`检查每条W记录的存在标志（W记录`+0`）。`0x4039C1`、`0x403A06`、`0x403B91`对W记录`+4`的**field/context数值**执行与`2`比较；另一个原资料/技能UI代码`0x427CF2`则比较其与`1`。这些是**本机对不同上下文可选择/显示技能的比较条件**，不是“技能效果为等级2”等语义。

`0x4047F0`从W记录`+8`的名字缓冲区取文字，进入战斗技能绘制调用。因而原版具有完整的本机链：**S/W接收数据 → 已验证缓存 → K允许的技能条目数 → 战斗技能菜单的存在/场域检查及名称显示**。这补充的是原版客户端内部行为，不能因此宣称恢复真正服务器的战斗计算。

## 新增二｜技能的目标类别为代码分派输入，不是硬编码技能效果表

原EXE`0x4033CD`从同一W记录的`+6`读取一个有符号short整数，并检查上界`7`，随后`0x4033DE`以该值进入最多8入口的跳转表。另一代码`0x403E80`也读取相同目标类型字段并分派。故可确认**原客户端存在按W数据的目标类别选择本机目标处理路径**；`0–7`是原程序分派的值域位置，**不是已证实的八种目标名称或技能伤害类型**。此项也不能被误写成“所有真实服务器技能都在0–7范围”或“原版拥有8个技能”。

## 新增三｜跨五宠物栏扫描已持有的技能ID

原EXE的`0x4250D0–0x425128`有可独立验证的技能ID存在性检索：

- `0x4250D8`令K容量/槽位结构迭代起点为`0x017F7698`，每宠进位`0x6C=108`字节；`0x4250E7`还检查K结构内另一个偏移`+104`的本地状态字等于1。**该状态字的具体游戏语义还未核实，不应推定是已上场、已登录或已发放。**
- `0x4250DD`令W首个技能数值ID起点为`0x017F7AEA`（W记录`+2`），`0x4250F7`检查其前两个字节的存在标志，`0x4250FD`按16位数与函数参数的ID比较。
- 在当前K给出的槽位容量之内，每条技能记录前进`0x6A=106`字节；每宠W缓冲区前进`0x2E6=742`字节，迭代终止条件的地址为`0x017F8968 = 0x017F7AEA + 5×742`。这**直接确认原生代码是最多5个宠物栏**，而非通过2016后期服务端的宏猜测。
- 查不到符合条件的技能时，`0x425122`清零结果，存在时进入返回1的路径；这是客户端**技能ID在已经接收的实例技能槽中是否存在**的查询，绝不是“按物种自动赋予该技能”。

## 新增四｜真正原始PC编译文件出现数值技能ID 200与201

`0x42A85A`以字面整数`0xC9=201`作为参数、`0x42A85F`调用上述检索；`0x42A883`以`0xC8=200`作为参数、`0x42A888`调用该检索。两条调用都在原版**已认证的实际PE可执行代码**中独立通过反汇编和原字节整数检查。

**严格不成立的推论：**不能仅凭这两个常量就声称ID200或201确在当年台湾官服正式技能主表中、对应某个技能名字或效果、出生已被任何宠物持有、属于某个宠物系，或与后期社区服务器同数字ID相同。它们当前只具有`VERIFIED_CLIENT_COMPILED_NUMERIC_SKILL_ID_REFERENCE`等级，技能正式投放/名字/服务器事件依然`null`。
