## 静态反汇编直接成立的链路

1. 原 `RegisterClassA` 前的窗口类初始化在 **0x41C56C** 将窗口过程地址设为 **0x41C970**，随后的 **0x41C5B7** 调用登记API。窗口过程在 **0x41D014** 按 `uMsg - 0x200` 分派，**0x41D40C** 为分支地址表，**0x41D434** 为每个消息的分支索引。
2. 原始消息映射由EXE中真实表字节与入口反汇编双核：

| Win32消息 | 原消息值 | 原处理入口 | 静态功能 |
|---|---|---|---|
| WM_MOUSEMOVE | 0x0200 | **0x41D034** | 从 `lParam` 拆出X/Y后调用0x42DED0 |
| WM_LBUTTONDOWN / UP | 0x0201 / 0x0202 | **0x41D196 / 0x41D1BA** | 转交0x42DF10 / 0x42DF70设置/清除输入状态 |
| WM_LBUTTONDBLCLK | 0x0203 | **0x41D1DE** | 转交0x42DFC0 |
| WM_RBUTTONDOWN / UP | 0x0204 / 0x0205 | **0x41D202 / 0x41D226** | 转交0x42E020 / 0x42E080 |
| WM_RBUTTONDBLCLK | 0x0206 | **0x41D24A** | 转交0x42E0D0 |

0x0207（中键按下）在该分派表中直接进入无操作的返回分支，0x0208等在本表走默认处理；不能从这一个表证明整个程序无其他输入来源。

3. **0x42DED0** 将上述坐标写入全局状态 **X=0x17E5DB8，Y=0x17E5DBC**，当原状态 `0x179BA70==1` 时对两个坐标做两倍变换，其用途不能擅称原游戏UI缩放方式。**0x425290** 与后续代码读取这两个状态，比较各自上下界，符合矩形坐标范围判定。另 **0x41EFD0/0x41EFE4** 将Y/X读成浮点数用于后续运算。前述是**原代码静态存在的具体输入→状态→消费路径**；矩形消费者的游戏对象/界面归属本轮没有证明。
4. 单独检查 DINPUT `DirectInputCreateA` 调用 **0x441705** 及源 GUID **0x452360**（`GUID_SysKeyboard`），可归类为原程序键盘设备初始化路径；**不能仅由该导入/API或上列鼠标消息推出捕获界面、战斗敌人等级、移动、宠物点击或原游戏执行成功**。原EXE未静态出现 `GUID_SysMouse` 这条完整常量，也不能据此推断所有鼠标通路不存在——Windows消息分派已有直接证据。
