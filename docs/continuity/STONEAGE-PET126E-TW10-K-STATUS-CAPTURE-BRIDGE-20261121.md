## 1. 同一原始客户端的可核验性

私人原始包 `StoneAge-TW1-original-runtime-and-native-observation-P3H.zip` 已在本轮重新实际读取、核 372,626,292 B 和 SHA256 `3a4854adaebef056332cdbd7b1dc1c130c571b11704e3f199f53d03aa31cba24`，全部 **379/379** ZIP 成员 CRC 通过。唯一分析对象是其中 `source/sa_3.exe`，425,984 B、SHA256 `cdab9ea049a98bbc96ce93eeaa8b63c688f0c0f0ad8b3183e79d75e47621441a`，与 [PET126C](STONEAGE-PET126C-TW10-ORIGINAL-BYTES-REACCESS-20261120.md) / [PET126D](STONEAGE-PET126D-TW10-CLIENT-CAPTURE-FIVE-SLOT-STATIC-20261120.md) 的来源一致。不重复计作新包。工具只对私人 EXE 计算局部 SHA/原地址关系；原商业 EXE、机码、完整数据表、SPR/REAL/位图均**不进入公开仓库**。

## 2. 新证据：原版 S/K 接收处理确实写入捕捉计数的槽位

现存 [TW1 客户端状态协议分层规范](../../research/clients/STONEAGE-TW10-GAMEPLAY-SCHEMA-R1.json) 已从原客户端证实接收 `S` 报文的类别 `K<digit>` 分派至 RVA `0x2FE94`；本轮直接重新静态读取 **原始 `sa_3.exe` VA `0x42FE94`**，补足它与 PET126D 本地五槽位计数的内存桥接：

| 原始入口或位置 | 从原字节直接确认的结构 | 严格限制 |
| --- | --- | --- |
| `0x42FE94`／文件偏移 `0x2FE94` | 由 `K` 后一位 ASCII 字符减 `0x30` 得到槽位编号；目标首地址 `0x017F7658`，每槽跨度 `0x6C` (108 B) | 当前入口**没有独立证成**所有调用路径的合法槽位编号校验；不据此猜测能否越界、是否实际可利用 |
| `0x2FEBD` 与 `0x2FEDC` | 同一 16 位成员标记地址 `0x017F76C0`（首槽 +104）；更新掩码为 0 时清标记，非 0 时写 1 | 不是证明服务端的宠物删除、出售或接收已成功 |
| `0x2FEE8–0x300DF` | 掩码值恰为 1 时，读取并填入 20 个后续字段，走**整项更新**路径 | 原字段语义如 HP/攻击等依早期生成协议谱系解释；代码静态指令仅证明参数解析与写入 |
| `0x300DF–0x30408` | 掩码非 0 且非 1 时，根据位标志分别更新后续 20 字段，同一字段全量/增量两路径目标地址一致 | 掩码不是“已证完整服务器封包行为”；不验证传输中的实际报文 |
| `0x4016D0` | PET126D 已证五个连续 108 B 槽的 **+104 处 16-bit 标记==1** 计数 | 客户端已占用槽计数，不等于角色账号或仓库总宠物上限 |
| `0x402354`／`0x404583` | 上述计数与 5 的两个局部比较，前者连接「捕捉」与「不能再捕獲更多的寵物了」的 UI 路径 | 不能凭客户端分支证明原服务器准许捕捉或真实收宠结果 |

**新成立的单源连接：** `S/K<digit>` 状态接收路径 **写入**的首槽位 `0x017F76C0` 正是 PET126D `0x4016D0` 沿五槽位数组读取的首标记；原 UI 列表以 108 B 跨度访问相同区域。这是客户端内部**写入→计数→捕捉界面门槛**的源级链，不是由另一年代私服源推断的相似函数。

## 3. 来源限定的字段布局

从原 EXE 静态还原，标记之外的每槽 108 B 容纳：**17 个连续 32-bit 字段（偏移 0..64）、两段在 +70 和 +87 处的本地名称缓冲区（各 17 B）、+104 的 16-bit 占用标记、+106 的 16-bit 数值字段**。对应原客户端 `S/K` 后续令牌 **2–21 共 20 个**；每一个都有整项写入与掩码增量写入的同目标地址，准确的 40 个源码立即数文件偏移和掩码见 JSON。

早期源谱系把这些字段依次命名为 `graphic_id, hp, max_hp, mp, max_mp, exp, max_exp, level, attack, defense, quick, ai, earth, water, fire, wind, max_skill_slots, rename_flag, name, free_name`。**字段序号与原 EXE 写入目的地是 TW1 直接证据；这些人类可读语义名称是 EARLY_LINEAGE 等级而非已回收原 v1 服务端主档。** 本轮没有从本地 EXE 识别全球宠物种类、原服唯一 PET ID、初始成长、学习公式或活服实发。

原二进制的 6 个相关小窗口分别发布 **半开文件偏移区间与窗口 SHA256**，不是窗口原文：`[0x2FE94,0x2FEE8)`、`[0x2FEE8,0x300DF)`、`[0x300DF,0x30408)`、`[0x26CF5,0x26D52)`、`[0x26A90,0x26B53)`、`[0x16D0,0x16EA)`。原源可复核性与公开 CI 的**派生元数据一致性**分别验收；后者不可冒称前者重读字节。若提供实际有权访问的私人原包，`tools/stoneage_pet126e_tw10_k_slot_audit.py` 能对原始 EXE 原偏移直接重算窗口、双路径 40 地址关系和旗标地址。工具**不运行 EXE**。
