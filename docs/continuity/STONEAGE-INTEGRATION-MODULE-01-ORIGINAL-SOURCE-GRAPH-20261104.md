## 1. 原NPC创建 → GetPet脚本 → 原任务控制段 → 原物品数值 → 来源地图

GAMEPLAY07真实取源的23份**直接有CREATE引用**的`GetPet`脚本，按原路径+原文件SHA+创建块ordinal与QUEST01原295脚本/315创建记录的源关系逐项联接，得到 **24条无歧义静态CREATE→脚本边**，全部原字节SHA相同。注意另4份`GetPet`保存源脚本没有直接CREATE引用，保留历史源文件并**不补造关联**；也不因文件夹名`event`就擅定属于节日活动。

23份脚本在原QUEST01已解析目录内共有**116个任务控制段**，原字面`DelItem`数字出现74次、`GetItem`18次、`predicate_ITEM`135次、`GetRandItem`82次，总**309个数字候选出现**、**101个不同编号**。这些101整数在ITEM01已确认证的两套原物品主表中**各有来源原行/行SHA**，并无候选缺项。注意某些原`GetRandItem`数字参数可能是配置权重/选择器等，不能仅凭碰巧存在于itemset就确认为真正物品代码，更不能宣传已通过任务、扣除/赠送或获得宠物；不同控制段也不能被臆测为已发生的单一路线。

同24条创建块原楼层引用共19个不同数值，与MAP01**客户端保存子树（组0）**的原 `.MAP/.DAT` 源成员索引联接：其中21条对应两份已成功读出、1条有原MAP但未读取DAT、2条未成功读出两者；**3条创建引用的原楼层在MAP01留有解包器读取错误**。原`3000`楼层的`.MAP`和`.DAT`属于这种失败项，绝不能记作游戏本身缺失两份场景文件。

举例：`giiru/event/ev28.create` 的五个真实原创建块分别引用 `ev28_ed1`—`ev28_ed5`，全部具有原楼层31706，MAP01客户端保存子树确实可读源`31706.MAP`和`31706.DAT`，QUEST01这些源脚本包含`GetPet`及原道具数值`2517`等；依每步原路径+SHA可重放**静态资料链**。但“角色实际上在31706能完成任务、宠物取得或道具消耗”仍没有同源运行验证。
