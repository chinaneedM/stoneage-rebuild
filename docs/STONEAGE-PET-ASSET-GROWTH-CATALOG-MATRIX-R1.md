# PET-ASSET-GROWTH-CATALOG-MATRIX-02 台湾1.0宠物身份—精灵—图像—成长实际连接审计

2026-10-17。历史同版本资料优先，不扩大末代被动反编译辅助函数。**本包专门寻找能直接作为未来人物/宠物图鉴资产索引的同版数据行。不得误称“宠物全部恢复”。**

## 已持有的真实源表和正确连接

已承认台湾1.0原始盘有确定性提取派生文件（只含元数据，无原始图片版权像素）：`ADRN-R1.tsv.gz`、`SPR-GROUP-R1.tsv.gz`、`SPR-ANIMATION-R1.tsv.gz`、`SPR-FRAME-R1.tsv.gz`，全部固定压缩源 SHA256，位于`research/recovered/tw10-resource-metadata/`。本轮新增`tools/stoneage_pet_asset_growth_catalog.py`直接遍历四份**全部**源记录、逐一核对索引、组、动画、帧与位图ID连接，用来证明**精灵组/动画帧→某原版图像编号**（而非仅验证文件总行数）。

样本选原SPR记录索引0—5、102、373、463。每行严格区分`group_index`、`spr_no`、`animation(direction,anim_no)`、`frame.bmi_no`与`ADRN.bitmapno`：帧中的`0xFFFFFFFF`为空图片占位，不应误入位图/物种列表。由实际CI报告提供九组各自真实的动画数、帧数、在ADRN找到的bitmap ID小样；不在文档中猜对应的是哪个宠物或者人物。

## 核心缺口不是图像文件是否存在，而是“这只宠物是谁”

原版客户端`S:K`21字段中的`graphic_id`已经有通信位置证据，但尚无当时原服`enemybase`及具体NPC/地图绑定的完整数据，**也没有经证实的`graphic_id→SPR group→动作→ADRN bitmap`同版跨表映射**。这需要原客户端实际查表/绘制调用图或可追溯的同代画面/运行踪迹。原资源组并非宠物种数，SRP帧数更不代表数量。

固定后代`recovered25`现有活跃`enemybase.txt`有988记录、次表640记录；当前Git只存源哈希与分布，不含该表原文本。活跃后代名称有988行、662个不同hash；Big5/cp950解释可解但尚有2条差异且运行时解码方式未定。它们是**后代敌人/宠物模板记录**而非“662种初代宠物”。`STONEAGE-25-RUNTIME-GRAPHIC-MAPPING-R1.txt`载明四个匿名资源映射token仍找不到对应文件/原值，也不能把已知后代姓名直接贴到原版SPR组上。成长公式只在后代源码得到部分互证，原JSS1999与台湾1.0各种宠物的原始基础成长配置和个体成长尚缺。

## 交付与验收原则

本包的**新可检查事实**是直接原盘派生格式的逐行跨表连接：原SPR组对应动画、真实帧→原图像索引的匹配情况与缺失情况，并输出可追溯来源的若干资源组行；不制造虚构宠物条目。独立工作流核实四份gzip哈希、125996/464/39065/242085原始资源规模，帧索引顺序及占位，输出 `CERTIFIED_RESOURCE_SAMPLE_JSON=` 可机读审计。后续把实跑样本和真实主线CI写入机器结果，才可计为该工作单元完成。

下一优先级：若实际能取得**与TW1.0同版图号→宠物模板姓名/成长/技能/产地**的史料，即为具名恢复；否则只把资源跨表完成记为`RESOURCE_CROSSWALK_CONFIRMED_PET_IDENTITY_OPEN`，紧接`ORIGINAL-UI-LOGIN-AVATAR-REVIEW-01`，按用户要求查真正角色/宠物与登录画面绑定；不在同一缺源下无限累加规范文档。现代单机游戏、美术、玩家网站和内挂仍不开始生产。
