# 《石器时代》跨模块资料档案法 R1｜从单只宠物逐步复原（2026-11-21）

**目的：** 用户确认“先用宠物做充分的单项模板，再把同一思路用于地图、装备、NPC等”。采用**最少必要公共字段 + 每个模块各自特有的字段**，不提前建一个庞大的通用游戏数据库。当前执行模块**仍仅 PET**，其他模块作为未来参考，不建立它们的恢复成果、数值或假索引。

## 一、未来各模块共用的六项原则

| 通用字段 / 工作方法 | 定义 |
| --- | --- |
| **自己分配的永久档案号** | 首次正式逐项建档时占号，不因改名、调序或原游戏代码更新而改号；原版所有编号另存并明确地区/版本 |
| **来源观察记录** | 每个客户端、官网公告、原图、原文本或档案单独记来源号/原行/截图/哈希；可有证据而未建立正式档案 |
| **版本差异** | 一份主档可以包含多个地区、时间、运营商/版本的逐项观察，但不能因同名/同数字直接认定是同一对象 |
| **资料与资源** | 文本、属性、坐标、图片、动作、音效、任务/掉落/交互等按实际存在的信息保留；版权原文件私人保存，只将依法可公开的元数据、索引与摘要放到Git |
| **证据等级与冲突** | 逐字段写原件/二手/候选/待证、不适用；保留矛盾版本和原文，不用后期资料无说明覆盖早期资料 |
| **可查进度** | 严格分开**来源候选条数**、**已建详细档案数**、**已核准完整条数**、**缺证条数**；总量未知时不报伪百分比 |

**“未知”不等于“0”，也不等于“游戏里不存在”。** `null` 表示未找到有效来源；“原版确无此项”需有对应版本可核验的否定证据。研究验收与未来游戏原创设定也必须分开。

## 三、实际推进时的简单流程（优先正确，避免复杂化）

1. **找到材料**：先查来源有别、年份明确的经典2D原版PC客户端/官网等，免费的可获得资料优先，历史材料按年份和地区分轨。
2. **立来源记录**：核原文件/原行SHA与准确载体，先列出候选；不能凭素材库图号推断官方发放。
3. **逐项建档**：每建立一份可查看的详情才分配永久编号；已有字段立即填入、没有的保持待证，图片动画私人观察。
4. **审查关联**：跨版同名/同图、NPC地点与地图、物品掉落与任务等只登记为“候选联系”；得到可靠的**双方来源**后再转为已证关联。
5. **更新进度**：自动/人工核对候选、建档、完整验收和已知缺口；一项条目完整不代表整个模块完成。
6. **模块收尾**：按PET→NPC→装备→地图→任务→玩法独立收敛；完成本模块并经过验收、取得用户明确解锁后，才转下一模块；后续各模块自身仍从最早可证版本重新核查。
