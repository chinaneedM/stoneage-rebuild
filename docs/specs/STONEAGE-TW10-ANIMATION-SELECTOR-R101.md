# R101：原台湾1.0动画选择、数据展开及帧倒计时规格

本包恢复一条可用于重构渲染器的具体规则：**对象图形字段→静态/动画分支→按方向/动作值选择动画→帧位图与偏移**，以及原始动画头的帧倒计时换算。没有把宠物名称接到原SPR，也没有运行原游戏画面。R100后的最高工作项要求同版选择链；这次直接使用原盘原程序，未扩大卡坦图组或R99静态资源列。

## 原源与方法

原SPR地址文件另实取5568字节/SHA256 `275b64ff55667aec633a7e82e09d65c84141380521f0f2e64c9a28e0d3aa6c25`。原已保管GROUP/ANIMATION TSV的压缩字节哈希完整固定；464组、39065动画是旧基数，不是本次新增宠物数。对原程序只保存5个有界代码窗口的哈希、40余条关键指令元数据及有限规则，不保存商业程序、光盘、SPR或像素。

Capstone静态解码与objdump独立核对关键地址。Unicorn只执行原x86的两个有界区域，使用**合成对象/表/动画/帧**；位图元数据助手0xe4e0被显式替换为零偏移、返回1，帧音效全0。它不是完整客户端启动、真实图像绘制、网络过程或历史服务器执行。原始字节哈希不符时拒绝进入分析。

## 选择与失败分支

- 非零倒计时先减1并返回，暂不选择下一帧；图形键或两个选择字段发生变化时会重置帧与倒计时。
- 键≤99清空选中位图；100—99999进入静态位图路径；键≥100000进入动画槽位路径。本包没有模拟静态位图辅助函数的真实IO/像素。
- 动画分支原上界比较为 **大于132768才跳出**，下界100000包含；加载循环只有32768个槽。上端点132768是否安全未证，规格原样记录比较符，不能默改成132767或宣称无越界。新引擎安全设计须另立决定。
- 动画槽位有动画数和指针；计数为0时保留此前位图，不是清空。实际图案或物种完全未知。
- 按对象0x134与0x12c匹配展开动画头的前两个16位值，按已知资源结构分别解释为方向与动作值。遇多个相同配对取第一条；找不到配对回退第0条，不返回“无动画”。没有给这些数字命名走路/攻击/骑乘等动作。
- 选定动画条目运行时16字节，帧条目运行时12字节；磁盘动画头12字节、帧10字节。原代码从磁盘帧展开出位图、带符号x/y偏移及音效字段。对当前帧取位图写0x80，合并帧偏移与辅助位图偏移，再推进帧索引。
- 帧达到尾部时，普通分支回到0；第三参数为1的有界案例返回1并写倒计时255。不能将该参数自行命名为“死亡”“一次性攻击”或断言全游戏动画模式只有两种。

上述10组合成状态均由**原指令**执行并与独立高层参考结果一致，涵盖第二条匹配、无匹配、重复配对、延迟、变更重置、空组、帧尾回绕、参数1帧尾、低键与超上界。位图1111/2222是合成测试数据，不是两只原宠身份。

## 原动画头倒计时换算

原加载代码0xe995—0xe9c4对正帧数执行无符号整数除法，并最小钳制1：

`countdown = max(1, floor(duration / (16 * frame_count)))`

例：duration1000、12帧→5；1000、7帧→8；64、2帧→2；duration0、正帧数→1。合成零帧数案例跳过除法与最小钳制，原duration保留；原39065个动画头实际零帧数为0。参考规则只覆盖分母不发生32位溢出的字段域，不伪造原输入校验。

同一份原动画元数据应用此新证实换算，倒计时最小1、最大75，帧数最大112。**倒计时单位不是已证毫秒**，没有在本包追游戏主循环更新频率，也不把1000除以帧数当最终画面FPS。10组原指令算术案例全部与参考规则相等。
