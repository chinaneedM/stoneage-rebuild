## 恢复对象与停止条件

目标不是再枚举几千个 NPC 模板，而是回答玩家实际会遇见的 NPC 放置、对白、选项、任务触发、条件、战斗、奖励、传送、任务存档是否有**同版本、可复核**数据。原始样本限定台湾 Waei/JSS 1.0 商业零售客户端；后期 recovered25、固定后代源码只能按 `LATER_RECOVERED` 的独立版本处理。若缺少同版商业服原始 NPC 数据或记录，就在具体边界停止，不编对白、不借后期脚本冒充原始任务。

## 影响玩家体验的六段内容链

1. **位置与发现**：TW1.0 NPC 人口/坐标不详；后期 create 机制不能补成首发 NPC。
2. **对白与窗口**：TW1.0 WN 通信形状成立，但对白、按钮外观与响应业务由服务器内容决定，仍缺失。
3. **条件与任务**：后期 WarpMan/Windowman/ExChangeMan 的门槛互不相同；不能因为字段名有 `giveitem` 就认作发奖。
4. **触发战斗**：后期 NPCEnemy 有可解析提示字段，仍无法确定原始任务遭遇和 NPC 野怪表。
5. **移动与奖励**：后期空间候选、购买、事件奖励三种证明不可混淆，更不能推成 TW1.0 确定剧情。
6. **任务持久化**：后代/现代保存模型尚未证明初代 SAAC 商业服的事件标记、背包持有与下次登录结果。

## 复原决策、重开条件与后续

**本包闭合的是「已持有资料中 NPC 内容能证明什么、不能证明什么」的有限审查，而不是补出初代任务。** 现有数据可以用于未来版本比较、现代实现的设计输入，但必须先保留来源版本。后期四出生点路线、条件传送和奖励存在性结果不提升为初代自然剧情。

仅在找到带校验和可下载的同版服务端 NPC/任务数据、真实初代 NPC 网络对话回放，或既有代表玩法链发生具体可证明冲突时重开对应单元；缺失 Windowman 四份 conff / TownPeople 参数可按 recovered25 的独立清理，不阻断全局 Stage A 审阅。停止继续追逐不改变玩家可见内容的普通辅助函数，原客户端 savedata R79 仍非阻塞。

**下一优先级：`STAGE-A-REVIEW-BLOCKER-TRIAGE-01`。** 以九族原有预检、四出生点、人物宠物、普通战斗与该 NPC 证据边界审查所有跨系统代表链，区分「有版本约束可运行」「有原客户端接口」「需原商业服务器内容」「永久开放并有重开条件」。九族仍 PARTIAL/OPEN，Stage A 未终验、Stage B GATED；不选择新引擎和美术，不报告无分母的复原百分比。
