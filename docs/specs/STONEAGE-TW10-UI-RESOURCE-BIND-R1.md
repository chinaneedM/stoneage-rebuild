# UI-RESOURCE-BIND-01：原始视觉资源到可见交互的有限边界验收

2026-10-16。台湾 Waei/JSS 1.0 原始客户端证据优先。**资源文件身份与战斗画面候选解码有界可用；游戏中真正如何选择战斗背景/调色板，以及宠物编号如何选到贴图/动画，仍然 OPEN。**

## A. 战斗背景

原始光盘 233 个 battle 地址记录：218 个 804 字节 SAB 场景，15 个按地址表索引的 SAP 调色板；光盘另有未索引的 Palet_0.sap。233 不是 233 个战斗场景。每个 SAB 有确证的 `SAB ` 4 字节头 + 400×2 字节单元。历史后代 ReadBattleMap 早期分支将其读成 20×20 的大端 u16 图像 ID；**该大小/结构组合强力支持解释，却尚非原始 sa_3.exe 解码调用链的直接证明**。仅测试一个号码是否存在于 ADRN 中无法确定端序。

新增 `tools/stoneage_tw10_battle_scene_spec.py` 为研究工具，读取现有已提交的原版地址记录，严格保持原版顺序并验证 218+15 和地址区间；可以将**合成或有合规来源的**完整 SAB 字节解释成候选 20×20 网格。输出中原版场景选择、调色板选择和显示调用一律为空，绝不凭 B 消息或 2.5 习惯擅自指定图片。

## B. 宠物图形身份

原版 S:K 的 21 字段结构与资源语料（125,996 个 ADRN 图像号、464 SPR 组）有直接来源；`graphic_id` 的**名称解释**来自早期生成协议谱系。尚未追到 original v1 客户端从 S:K 字段经过哪段代码查表、选择哪个 SPR 组、哪个动画、哪一帧，也无法从资源数量推出映射。后期 recovered25 的匿名 ls2data 图形映射审核目前 4 个 token 映射缺席，更不能补成原版映射。

## 结论与停止条件

本包只验收：原始 SAB 地址索引源证明、候选布局解码规格及合成负面边界；宠物 GUI 实际选择映射与战斗场景运行选择暂不闭合。缺口需要 **v1 sa_3.exe 相关调用图/执行轨迹、可归属的资源选择输入及原始版本证据** 才重开，而不是继续堆积音效、资源编号或现代渲染测试。

机器可读审计：`research/recovered/STONEAGE-TW10-UI-RESOURCE-BIND-SCOPE-R1.json`。Stage A 九系统仍 PARTIAL/OPEN；Stage B GATED；R79 本地 savedata 支线暂停。下一项回到游戏内容复原：**STAGE-A-NPC-CONTENT-BOUNDARY-01**，有限核对早期 NPC/任务/对白的现存证据和后期版本来源缺口，不制作新游戏内容。
