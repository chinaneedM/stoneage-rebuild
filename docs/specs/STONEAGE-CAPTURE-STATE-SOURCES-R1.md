# PET-STATE-01：捕获、宠物栏、保存与成长的状态来源

2026-10-16。版本范围：已有固定后代捕获规则和后期桥接参考模型；不是台湾1.0商业服务器的完整重现。所有试验数据均为独立构造值，没有执行原客户端或读取原始存档。

## 结论与实际改动

捕获公式、第一次空宠物栏位置、捕获不产生击杀收益的规则已有模型。当前缺口主要在完整宠物状态的来源，不能把出生函数重新运行一遍当成捕获。

本次统一直接捕获与回合捕获的状态检查：已知野生敌人名称必须复制；若提供隐藏成长状态，捕获时VARIABLEAI必须是0。错误值在安装宠物前拒绝；不静默改写隐藏值，以免和调用方提供的可见AI不一致。原有身份、宠物栏、等级、HP及maxHP检查继续有效。未知来源名称、缺少成长身份仍明确由外部负责，不补造。

一个现有桥接测试原本断言GET=11，却没有在该测试输入中提供GET。本轮在未改动的远端测试副本重现失败，修正测试输入，并保留缺少GET时capture_default=None的检查；没有给生产模型增加默认捕获参数。

## 字段与载体

| 状态 | 已有规则/来源 | 当前载体与边界 |
|---|---|---|
| 敌人变体、模板、宠物栏 | 野生目标身份与第一次空槽 | 两捕获入口均核对，不能混用运行对象ID/模板ID/槽位 |
| 等级、当前HP、maxHP | 当前目标快照；基础捕获模型复制HP，参数重算另有边界 | 当前运行时有直接核对；maxHP核对是现有参考模型的投影合同，不扩张为任意状态变换下的商业规则 |
| 名称 | 固定后代模型复制野生目标当前名称 | 本次增加已知名称一致性检查；未知名称不推定 |
| MP、maxMP | 固定后代捕获模型复制当前敌人值 | 最小BattleParticipant没有这两个字段；其他运行时overlay不能因此被宣称不存在。当前捕获仍需明确供应 |
| 内部四属性、PETRANK、ALLOCPOINT | 固定后代捕获复制当前成长身份 | **SpawnedEnemy.birth及LocalRuntimeBattleContext.spawned_enemies仍保存出生身份**，并非所有载体都丢了；出生值不能无条件等同战斗变换后的当前值 |
| VARIABLEAI | 已有模型在捕获成功后归零 | 本次拒绝提供非零隐藏值；可见固定AI需要另外的主人/参数合规来源，不能直接等同MODAI |
| EXP | 已有模型明确不复制敌人EXP | 敌人reward_exp是击杀奖励，不是宠物当前EXP；初始EXP仍需明确来源 |
| maxEXP | 已有模型说明按等级重新计算 | 必须选择有来源的阈值/版本配置；不默认后期表为初代规则 |
| 技能、状态、四属性、图像 | 已有捕获复制字段与模板/运行时语义 | 静态技能ID不足以证明当前技能/使用状态；完整PetSkill视图与当前状态仍显式供应 |
| renameFlag、freeName等初始化字段 | 桥接构造器要求显式输入 | 不从捕获成功、模板名字或默认0猜出原始初始化政策 |
| 保存与再次使用 | 参考模型PetActor.state、skills、growth及R4保存格式 | 持久化保留完整提供值；不保存旧运行对象ID；现代保存成功不证明历史SAAC或客户端文件成功 |

## 有界玩法链验证

新增六项针对行为的回归，其中正向场景使用真实临时磁盘文件和新建的协调器实例：

1. 提供来源明确的独立构造宠物快照，执行普通捕获回合，敌人退出且玩家不获击杀EXP；原会话保持未修改。
2. 结算到宠物栏，保存并由新实例重新读取；逐字段比较MP/EXP/名称/状态扩展、技能视图、成长身份。
3. 再次入战，显式选择新捕获宠物参战；捕获不自动把它设置为默认宠物。
4. 用**显式准备的终局EXP奖励**、阈值配置和成长随机数验证后续升级，再保存/读回。PETRANK与ALLOCPOINT保持，VARIABLEAI从0变500；HP不自动恢复，MP和技能不被重置。

步骤4不是自然击杀分配证明，数字500/900和试验状态都不是历史原始数值。新增反例验证错误名称、未归零VARIABLEAI在两个入口拒绝且不写入宠物栏；未知名称/未知成长保持边界。

## 处置与停止条件

PET-STATE-01本轮交付：字段来源表、两项正面证据支持的最小修复和完整输入条件下的生命周期验证。

**完整宠物自动构造仍OPEN，处置为EVIDENCE_LIMITED_EXPLICIT_STATE_REQUIRED。** 尚未获得足以统一当前MP、初始化EXP/maxEXP、完整技能/状态及可见AI来源的匹配运行状态。不为了关闭此标签追加无边界研究；缺数据时保留显式输入，成长身份缺失时升级仍应拒绝。
